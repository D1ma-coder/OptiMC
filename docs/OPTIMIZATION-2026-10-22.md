# Оптимизация подготовки кадров, 22 октября 2026

Изменения не уменьшают дальность, детализацию, разрешение или частоту сетевой
синхронизации. Окно, Vulkan и GPU не запускались: действует ограничение из
[диагностики WindowServer](GPU-INCIDENT-2026-10-20.md).

## Подготовка сцены

- `RemoteMesher` сравнивает идентичности immutable Arc-колонок до сортировки
  чанков, построения семи соседних stamp на секцию и сборки portal graph.
  Изменения сущностей, карт и metadata используют прежнюю геометрию блоков.
  Замена/удаление колонок и смена измерения инвалидируют кэш; отмена проверяется
  и на быстром пути. Ссылки на старые колонки удерживаются до следующего обновления.
- Поиск готового GPU-меша заменён с линейного обхода каждого старого меша на
  индекс по Arc-идентичности. Индекс перестраивается при публикации набора;
  дополнительно проверяются границы и Arc::ptr_eq. Для N одинаковых мешей
  прежний проход требовал N(N+1)/2 сравнений; новый — N поисков в HashMap.
- Диапазоны polygon LOD делятся через Arc вместо отдельной аллокации массива
  при каждом клонировании GpuMesh.
- Непрозрачные/прозрачные draw lists собираются одним проходом с общей проверкой
  frustum и section occlusion. Векторы сохраняют capacity между кадрами.
  Расстояние прозрачного меша вычисляется один раз; сортировка in-place сохраняет
  прежний порядок при равных расстояниях явным сравнением исходных индексов.
  Тени продолжают использовать собственный light frustum.

## Измерение

CPU-only debug benchmark `world::remote_mesh::tests::benchmark_unchanged_terrain`:
421 неизменившаяся колонка, 842 пустые секции, 200 обновлений.
Принудительный прежний обход секций: 600,73 мс суммарно; быстрый путь: 20,06 мс.
Это примерно 3,00 → 0,10 мс на обновление данного участка. Старый путь в тесте
включает и обслуживание нового кэша. Пустые секции изолируют стоимость обхода;
это не полноценный игровой мир, не профиль всего кадра и не доказательство
роста FPS в 30 раз. GPU submission, тени, fill rate и presentation не измерялись.
Лог: `.cache/optimization-world-cpu.log`. Benchmark не содержит порога по времени.

## Чанки и оставшиеся сетевые задачи

JAR SHA-1 `2dc72797acbc1b63fc16a11c4ac393605f453754`,
`LevelChunkSection.read(FriendlyByteBuf)`: два readShort сохраняются без проверки
диапазона. Убрана наша дополнительная проверка `Invalid section occupancy`.
Счётчики сохраняются как исходные 16 бит; они не задают длины выделений памяти.
Ограничения размера пакета/буфера секций, числа секций, ширины и индексов палитры
сохранены. Ошибки палитры теперь включают координаты чанка и индекс секции.
Bytecode-аудит: `.cache/protocol-audit/chunk-section-read-26.2.txt`.
Регрессия проверяет счётчики 4097/32767/32768/65535, обрезанные секции и плохую
ширину палитры. Исходный проблемный пакет пользователя не сохранён в этой
проверке; отсутствие повторного кика на публичном сервере не подтверждено.

Пакеты animate 0x02, set_passengers 0x6b и update_advancements 0x82 остаются
неполными. Metadata 0x63 имеет частичный обработчик и явный отказ для неизвестных
сериализаторов; полное покрытие протокола не заявляется. Повторная конфигурация
очищает прежний мир; успешное восстановление конкретной сцены из лога требует
дальнейшей проверки. Эти задачи не заменены оптимизацией.

## Накопленные изменения инвентаря и текстур в этой сборке

- Серверные клики PICKUP, QUICK_MOVE, SWAP, CLONE, THROW, QUICK_CRAFT, PICKUP_ALL;
  LMB/RMB, Shift, double click, 1–9, F, Q/Ctrl-Q и распределение перетаскиванием.
  События упорядочены; клики ограждены world epoch, menu serial/id и размером
  контейнера; worker подставляет актуальный server state id. Очередь — 256.
- Визуальное предсказание обычных storage menus и player storage, preview drag.
  Новое серверное состояние всегда имеет приоритет; специализированные
  crafting/equipment restrictions пока остаются на сервере.
- Wire-предсказание ещё не реализует native HashOps: changed slots отправляются
  пустыми, carried hash — EMPTY. Сервер выполняет действие и корректирует клиент.
  Это может давать больше корректирующих пакетов; полная vanilla-предикция не заявляется.
- `container-clicks.json.gz` содержит оригинальные StreamCodec байты всех типов
  кликов; `container-prediction.json.gz` — 18 последовательных состояний настоящего
  ChestMenu.clicked из JAR. Rust сравнивается с ними после каждого действия.
  Java helpers находятся в `tools/reference/ExportContainer{Clicks,Prediction}.java`.
- Иконки семи типов голов строятся из оригинальных моделей и PNG. Cache key
  учитывает item_model и profile skin; публичные texture properties используются
  без входа в Ely.by. Не разрешённые по имени профили пока имеют default skin;
  остальные special renderers и held heads ещё не все перенесены.
- Mipmaps текстур вычисляются в линейном RGB с учётом alpha и без влияния RGB
  полностью прозрачных пикселей. Это устраняет найденный источник потемнения
  листвы при смене texture LOD/разрешения. Silhouette, filtering и postprocess
  всё ещё могут различаться между разрешениями; попиксельное равенство не заявляется.

Проверки и идентификатор собранного приложения приведены в STATUS.md.
