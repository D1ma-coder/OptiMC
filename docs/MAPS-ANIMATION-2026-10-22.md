# Карты и серверные взмахи, 22 октября 2026

## Отключение Map cache limit exceeded

Причина данного сообщения — дополнительный hard limit 256 map IDs в нашем
`net::maps::Store`, а не серверный disconnect packet. Он удалён после сверки
`ClientLevel.getMapData/overrideMapData` в исходном 26.2 JAR: оригинал хранит
mapData по ID без такого порога. Карты сохраняются для дальнейших частичных
патчей, а не вытесняются с потерей пикселей. Как у оригинала, расход памяти
зависит от числа полученных карт; карта содержит 16384 индексированных цвета.
Пустые карты теперь делят immutable нулевой массив до первого изменения.

При обычном respawn данные карт сохраняются; play login / повторная
configuration создают новый store, как и прежде. Отдельно исправлена жизнь
мешера: на смене world_epoch создаётся новый RemoteMesher и сбрасываются
снимки пикселей/версий. Оставшийся от предыдущего уровня атлас больше не
накапливает недоступные карты, текстуры блоков и сущностей после переключения
уровня. В пределах одного уровня GPU texture array всё ещё имеет аппаратный
предел; отдельный atlas paging ещё не реализован.

Доказательства:

- Unit test: 1024 различных карты, частичные патчи ID 0/255/256/1023,
  сохранность прежних пикселей и независимость опубликованного snapshot.
- Localhost TCP test: 1025 карт в настоящих framed/compressed пакетах 0x33
  проходят через live session без отключения; последующие пакеты принимаются.
- CPU test prepare_epoch: при прежней эпохе текстуры сохраняются, при новой
  освобождаются; текущий мир после этого снова строится с тем же числом текстур.
- Bytecode: `.cache/protocol-audit/clientlevel-map-storage-26.2.txt`.

Публичный сервер и GPU для проверки не запускались; исчезновение всех ошибок
данного сервера не заявляется.

## Animate 0x02: обычные взмахи

Добавлены точный VarInt+unsigned byte codec и обработка действий 0/3 — основной
и второй руки. Состояние публикуется в SessionReport, очищается при удалении/
повторном использовании entity ID и смене мира. Повторный взмах принимается
после половины длительности. Учитываются haste/conduit power и mining fatigue;
базовая длительность пока 6 тиков. Equipment-specific swing_animation, смена
эффектов посреди уже начатого взмаха и точное совпадение фазы игрового тика
оригинала ещё не реализованы: графическая фаза привязана к монотонному времени.

В экспортированных моделях с head/body/right_arm/left_arm отмечены части
скелета. Для них применяется обычная WHACK-ветка HumanoidModel: поворот корпуса,
перенос плеч, quartic easing, наклон головы и зеркальная рука. Physical arm
выбирается по оригинальным индексам Mob/Avatar metadata и off-hand.
Обновления поз продолжаются между входящими пакетами (до одного запроса на
16 мс), затем возвращается нейтральная геометрия и её кэширование. Неизменившаяся
геометрия блоков использует быстрый путь прошлого цикла.

Это базовая ветка HumanoidModel, а не полный перенос всех entity-specific
setupAnim overrides. Отдельные zombie/piglin/skeleton/weapon poses, STAB/NONE,
player skins/models, локальная third-person анимация и другие специфичные
renderer paths требуют дальнейшей работы. Действия wake-up 2, crit 4 и magic
crit 5 не подменены взмахом: для них остаются явные unhandled diagnostics.

Точность математики проверена вызовами оригинального метода из JAR:
`tools/reference/ExportHumanoidAttack.java`. 272 комбинации фазы (0..1), руки,
наклона головы и ageScale. Rust использует оригинальную 65536-entry sine table
и правила индексации Mth; обычный sin давал выявленное расхождение.
Результаты: `data/26.2/humanoid-attack.json.gz`, `animate-packets.json.gz` (24
реальных StreamCodec пакета), `animation-metadata.json`; SHA-1 записаны в
reference.json. CPU geometry test проверяет движение, сохранение площади/UV,
возврат в нейтральную позу и повторное использование готового меша.

## Проверки и незавершённая работа

263 проверки прошли: 228 library, 10 world CPU (включая benchmark), 1 epoch CPU,
16 localhost TCP, 5 Naga, 3 item icon CPU. Clippy all-targets -D warnings, fmt,
release compilation, cmp packaged binary и plist проходят. Sandbox linker
cache warning не помешало сборке. Окно/GPU не запускались после прежнего
WindowServer инцидента; пользовательский процесс/настройки не менялись.
Повторяющийся Live scene теперь печатается при изменении счётчиков, либо всегда
с OPTIMC_NET_TRACE, вместо одинакового сообщения при каждом обновлении сущностей.

Из последнего лога ещё не завершены set_passengers 0x6b, block_event 0x07,
level_event 0x2e, damage_event 0x19, update_advancements 0x82 и часть metadata
codecs. Их диагностика сохранена; наличие обработчика прочих пакетов не
объявляется полным покрытием протокола. Общая цель не завершена.
