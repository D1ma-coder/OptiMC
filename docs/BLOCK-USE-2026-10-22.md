# Выбор и использование блоков: первая игровая интеграция

Предыдущий цикл цели дал реальное продвижение: серверный polygon LOD и shader
LOD подключены и упакованы. В этом цикле проверены игровые действия: до изменений
Request содержал только чат/подсказки, клики в Playing не отправляли действия.
Полный перенос взаимодействий пока не завершён.

Добавлены:

- Отдельные outline shapes из официального 26.2 JAR: 32366 состояний, 860
  переиспользуемых форм. Они отличаются от collision и camera visual shapes;
  например, стекло выбирается лучом, хотя camera visual shape у него пустая.
- CPU clipping: точка, сторона, inside-флаг; DDA по загруженным серверным ячейкам
  с соседями для выступающих форм. Направление идёт от игрока, не от сглаженной
  камеры третьего лица. Координаты глаза сохраняются в double. Дальность берётся
  из серверного minecraft:block_interaction_range, fallback штатный 4.5.
- ПКМ главной рукой и повтор каждые четыре завершённых physics ticks при
  удержании. Потеря захвата мыши/меню сбрасывает удержание. Нет автоматической
  отправки без пользовательского нажатия.
- ServerboundUseItemOnPacket 0x42: hand, packed BlockPos, Direction, три float
  смещения, inside/world-border flags и VarInt sequence. Перед действием
  синхронизируются текущие selected slot и input/sneak. Очередь ограничена;
  просроченные world epoch/teleport targets отбрасываются.
- Номера действий идут из socket worker, начиная с 1 в новом мире.
  ClientboundBlockChangedAckPacket 0x05 декодируется и сохраняется в snapshot;
  состояние мира продолжает поступать от сервера, локального удаления блоков нет.

Сверка с оригиналом: tools/reference/ExportOutlineShapes.java и ExportUse.java,
данные outline.json.gz и use-reference.json.gz, SHA-1 в data/26.2/reference.json.
JDK нужен только разработчику для получения этих эталонов; runtime без Java.
1800 лучей по 9 обычным/неполным формам сравнивают точку/сторону/inside с
VoxelShape.clip JAR. Те же лучи проверяют обход server-world. 24 packet fixtures
сравнивают обе руки, шесть направлений и inside-флаг побайтно, включая отрицательные
координаты и world-border flag. Runtime пока использует только главную руку.

Loopback TCP regression проходит framing/compression/session: selected slot и
приседание приходят до use, две допустимые операции имеют sequence 1/2,
просроченные epoch/teleport операции отсутствуют, серверные ACK доходят до snapshot.
Сначала отправляются накопленные корректные motions, затем актуальное действие,
чтобы старое движение не возвращало предыдущий selected slot после ПКМ.

**Обновление следующего цикла:** базовый приоритет сущностей перед блоками,
entity attack/use и рамки/стойки добавлены; доказательства и границы —
[ENTITY-PICKING-2026-10-22.md](ENTITY-PICKING-2026-10-22.md). Полная семантика
динамических hitbox всё ещё не завершена. Требуются original interaction-shape override,
entity-sensitive контекст форм/world border, offhand fallback, локальная
проверка InteractionResult и item cooldowns, hand animation, prediction/ACK
reconciliation, server inventory/контейнеры и их UI. ACK сейчас является
подтверждением номера, а не завершённой системой предсказания. Spectator use
в этой интеграции отключён. Левый клик/добыча/attack и tool/effect parameters
остаются следующими существенными задачами; полная vanilla parity не заявлена.

179 library + 13 loopback TCP + 5 Naga + 8 CPU geometry = 205 passed.
Clippy all-targets -D warnings и fmt проходят. Логи .cache/use-*-tests.log и
.cache/use-clippy.log. GPU, окно, внешние серверы и антибот-проверки не запускались.
