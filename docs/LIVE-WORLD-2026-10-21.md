# Живой мир, сущности и ошибка высоты чанка

Общая цель полного клиента остаётся активной. Эта контрольная точка не означает полного переноса всех сущностей или успешного прохождения серверной проверки.

## Проверенные причины

CPU-инспекция `mclucky.me` сохранила последний мир даже после серверного отказа. В `.cache/void-live-inspection.log`: позиция `[7.5, 200, 7.5]`, измерение `min_y=-64`, `height=384`, девять чанков по 24 секции. Все 884736 состояний блоков — ID 0 (воздух), сущностей нет. Мешер закономерно возвращает 0 мешей. Затем сервер прислал отказ антибота. Это свидетельство конкретной проверочной сессии; оно не доказывает отсутствие ошибок отображения в других мирах и не объясняет, какая проверка сервера не прошла. CPU-инспектор не выполняет автоматические действия проверки, не решает задания и не использует GPU.

Новый пользовательский journal `session-1792600826918101000-37300.json` фиксирует другой случай: локальная ошибка `Chunk section count does not match dimension height` на первом чанке размером 74638 байт. Прежние журналы не сохраняли число разобранных секций и параметры измерения; точная структура этого пакета неизвестна.

Сопоставление с официальным JAR выявило реальное различие: `LevelChunk.replaceWithPacketData` обходит массив секций измерения, тогда как наш прежний `chunk::decode` читал до конца массива байтов. Runtime теперь использует `decode_for_dimension`: читает фиксированное число секций, сохраняя ограничения размера и проверку усечённых данных. Неиспользованный хвост section-buffer не превращается в дополнительные вертикальные секции. Bytecode сохранён в `.cache/protocol-audit/chunk-section-read-reference.txt`. Unit и настоящий локальный TCP regression содержат 24 секции плюс padding, воспроизводящий прежнюю ошибку. Повторное подключение к серверу из нового скриншота ещё требуется для подтверждения именно его случая.

## Добавленная реализация

- `map_item_data`: оригинальная палитра, полные/частичные пиксели 128×128, сохранение/очистка декораций. Метаданные рамок используют индексы 9/10/0 из оригинала, а не старые 8/9.
- Рамки и светящиеся рамки используют официальные модели. Карты передаются в живую сцену четырьмя тайлами 64×64, без уменьшения разрешения. Изменённый участок обновляет только затронутые тайлы; неизменная геометрия переиспользуется.
- 90 базовых моделей сущностей из официального каталога подключены к сетевой сцене. Появление, положение, поворот головы, удаление и поддерживаемый флаг невидимости обновляют меши. Ревизия Tracker теперь пробуждает mesh worker для обычных сущностей.
- Официальные текстуры сущностей разделяются по границам тайлов без ресемплинга. UV-clipping сохраняет площадь поверхностей; отрицательные UV и повторение относительно исходных размеров текстуры сохраняются. Проверены все 90 моделей, точные пиксели, повторное использование геометрии и серверное перемещение/удаление.
- Worker передаёт версии текстур; рендер порционно загружает изменившиеся слои и проверяет согласованность массива пикселей и версий. Для карт и пикселей сущностей выбирается mip 0.
- Журнал хранит только последние 16 сводок чанков: координаты, число секций, заявленную занятость и число декодированных ненулевых state IDs. Ненулевой state ID не всегда означает не-воздух (есть cave_air/void_air); raw блоки в journal не записываются.
- 23 поддерживаемых ItemStack component payload проверены на байтах официальных stream codecs. Development exporter не нужен клиенту во время работы.

## Границы проверки

CPU/TCP/Naga не заменяют визуальную проверку Vulkan. После WindowServer incident графический клиент агентом не запускался. Не добавлены все специальные entity renderers, модели игроков со скинами сервера, оборудование, варианты, анимации конечностей, специальные block entities. Декорации карты пока хранятся, но их значки/подписи не рисуются. Полная синхронизация протокола и устранение отказа антибота остаются незавершёнными.

Воспроизведение без GPU:

```sh
cargo test --all-targets
cargo test --lib world::remote_mesh -- --ignored
cargo clippy --all-targets -- -D warnings
```

Тесты с `--ignored` требуют уже импортированных официальных ресурсов. Логи этой контрольной точки: `.cache/void-all-tests.log`, `.cache/void-official-geometry-tests.log`, `.cache/void-clippy.log`.

Результат: 149 library + 12 TCP + 5 Naga = 166 passed; отдельно 4 проверки официальной геометрии passed. Clippy all-targets `-D warnings` и `cargo fmt --check` прошли. Release собран и `.cache/OptiMC.app` обновлён без запуска; Info.plist прошёл `plutil -lint`. SHA-256 упакованного executable и `target/release/optimc`: `d829b10f12c158c14af2137b77ee5a8cb0c5cc3e569fcdb6c79e0090a53c536b`. Предыдущий executable сохранён как `.cache/OptiMC-before-live-entities`. Уже открытый клиент не закрывался и автоматически не перезапускался. Обновлённый аудит протокола: 61 partial handler, 106 missing handler; полный semantic parity по-прежнему не заявлен.
