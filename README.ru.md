OptiMC — независимый клиент Minecraft Java 26.2 на **Rust** с отрисовкой через **Vulkan / wgpu**. Сетевой обмен, хранение мира, построение мешей, интерфейс и симуляция игрока реализуются в проекте. Приложение не запускает Java-код Minecraft и не содержит JVM.

Проект ориентирован на сетевую игру, производительность и настраиваемую детализацию. Официальные ресурсы скачиваются или импортируются локально. Встроенного сервера и одиночной игры нет.

**Экспериментальная версия.** Серверный мир, инвентарь и взаимодействия уже реализованы, но полная совместимость с оригиналом ещё не достигнута. Часть пакетов и моделей сущностей отсутствует или поддерживается частично. Точные ограничения: [покрытие протокола](docs/COVERAGE.md) и [состояние разработки](docs/STATUS.md).

## Возможности

| Область | Текущая реализация |
|---|---|
| Сеть | Offline-mode вход, configuration registries, сжатие, keepalive, телепорты и переходы между мирами; protocol 776 |
| Мир | Серверные чанки, изменения блоков, официальные модели, переиспользование мешей и общие снимки состояния |
| Игрок | Движение, коллизии, камеры от первого/третьего лица, сглаживание, атака, использование и добыча |
| Интерфейс | Главное меню, список серверов, локальные профили, чат с подсказками, хотбар, инвентарь, HUD, Tab и scoreboard |
| Особые объекты | Рамки с картами, таблички с редактором, сундуки и отдельные сущности; поддержка неполная |
| Графика | Low/Medium/High, тени и постобработка, масштаб GUI, разрешение рендера, лимит FPS и режим вывода |
| Оптимизация | Фоновое построение мешей, кэширование, отсечение и настройка детализации; отдельное демо quadtree LOD |

Локальные профили поддерживают скины Ely.by **без входа в Ely.by**. Авторизация Microsoft и Realms не реализованы. Подключение к старым версиям через ViaVersion ещё не поддерживается: текущий перенос охватывает кодеки таблиц соответствий.

## Сборка

Нужны **Rust 1.88+**, системный компилятор и драйвер с поддержкой Vulkan. Для разработки используется stable Rust.

```sh
git clone https://github.com/D1ma-coder/OptiMC.git
cd OptiMC
cargo build --release --locked
cargo run --release --locked -- assets sync
cargo run --release --locked
```

`assets sync` загружает официальные метаданные и ресурсы Mojang, проверяя SHA-1 JAR. Можно импортировать уже скачанный клиент:

```sh
cargo run --release --locked -- assets import /path/to/26.2.jar
```

Ассеты, профили и настройки хранятся в игнорируемой `.cache/`. Другой каталог задаётся через `OPTIMC_CACHE` или `--cache`. Скачанные JAR, текстуры, бинарники модов и личные профили в репозиторий не включены. В `data/` находятся отчёты, тестовые данные протокола и таблицы соответствий с описанием происхождения.

| Платформа | Графический runtime | Проверки |
|---|---|---|
| macOS Apple Silicon / Intel | Vulkan через MoltenVK | Разработка на Apple M2 Pro; последние проверки — CPU/TCP |
| Windows | Vulkan loader и драйвер GPU | Проверки сборки настроены в CI; тестирование на оборудовании впереди |
| Linux | Vulkan loader и драйвер GPU, X11 или Wayland | Проверки сборки настроены в CI; тестирование на оборудовании впереди |

На macOS установите [Vulkan SDK](https://vulkan.lunarg.com/sdk/home#mac) либо поместите MoltenVK в `.cache/runtime/lib/libMoltenVK.dylib`, а `libvulkan.dylib` сделайте ссылкой на него. Подробнее — [упаковка приложения](docs/APP-PACKAGING.md). Во время прошлых GPU-экспериментов произошёл сбой macOS WindowServer; ограничения графических проверок описаны в [отчёте](docs/GPU-INCIDENT-2026-10-20.md).

## Подключение

Откройте приложение и выберите «Сетевая игра» либо используйте команду:

```sh
cargo run --release --locked -- status localhost:25565
cargo run --release --locked -- play localhost:25565 --username OptiPlayer
```

Поддерживаются Java-серверы с `online-mode=false`. Плагины авторизации могут требовать действий в чате. Совместимость с античитами не гарантируется.

Диагностическое подключение без игрового окна:

```sh
cargo run --release --locked -- connect localhost:25565 --username OptiPlayer --seconds 30
```

## Управление

Для основных действий используются физические клавиши, включая T/E независимо от раскладки.

| Ввод | Действие |
|---|---|
| WASD, Space, Shift, Ctrl | Движение, прыжок, приседание, бег |
| Мышь / ЛКМ / ПКМ | Обзор / атака или добыча / использование |
| E | Инвентарь |
| 1–9 / колесо / F | Хотбар / прокрутка слотов / смена руки |
| T / клавиша слеша | Чат / чат с `/` в начале |
| Tab | Список игроков; дополнение текста в чате |
| F5 / F1 / F3 / F11 | Вид камеры / скрыть HUD / отладка / полный экран |
| Esc | Закрыть экран или открыть меню паузы |

В инвентаре поддержаны ЛКМ, ПКМ, Shift-перенос и другие режимы клика. Предсказание и правила специализированных контейнеров ещё не полностью перенесены; сервер остаётся источником истины.

## Графика и производительность

В настройках доступны масштаб GUI, пропорциональное разрешение сцены от HD до разрешения экрана, ограничение FPS, режим вывода, пресеты качества и детализация.

- **Low:** классические текстуры и простое освещение.
- **Medium / High:** собственные WGSL-эффекты с ориентиром на BSL/Bliss. Это не полные порты этих шейдерпаков.
- **VSync выключен:** используется Mailbox, а при его отсутствии — FIFO. Immediate исключён, чтобы избежать разрывов; при FIFO частота вывода по-прежнему может ограничиваться частотой экрана.
- **LOD:** настраиваемая детализация и бюджеты геометрии/шейдеров. Постоянного дискового кэша дальнего серверного мира пока нет; клиент не рисует чанки, которых сервер не передавал.

Сеть и построение геометрии работают отдельно от окна. Общие снимки, повторное использование CPU/GPU-мешей, ограниченные очереди и порционная загрузка сокращают повторную работу. FPS зависит от сцены, качества и оборудования; отдельные CPU-замеры не считаются измерением общего прироста FPS.

Процедурное демо и CPU-бенчмарк:

```sh
cargo run --release --locked -- demo --radius 1024
cargo run --release --locked -- bench --radius 1024
```

## Разработка и проверки

```sh
cargo fmt --all -- --check
cargo clippy --locked --all-targets -- -D warnings
cargo test --locked --all-targets
```

Обычный набор включает CPU-проверки, валидацию шейдеров и локальные TCP-fixtures. Тесты с GPU и локальными ассетами по умолчанию игнорируются. Не запускайте `--include-ignored` как повседневную проверку. Java-инструменты в `tools/reference/` нужны только для проверки поведения эталонных классов при разработке.

Среди оставшихся задач — рецепты, достижения, пассажиры, экипировка и части metadata/анимаций сущностей. Свет и погода принимаются и сохраняются, но ещё не полностью подключены к отрисовке. Требуют работы respawn, полная поддержка шрифтов и специальные инвентари. [Отчёт покрытия](docs/COVERAGE.md) различает частичную обработку и отсутствующие функции.
